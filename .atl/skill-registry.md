## Compact Rules (project-relevant skills)

### next-best-practices
- Follow Next.js App Router file conventions; RSC boundaries: keep server/client split explicit ("use client" only where interactivity requires it).
- Use async APIs for data fetching in server components; no synchronous fs/db access in client bundles.
- Route handlers / API Routes for server-only logic; never import client-only modules there.
- Metadata via exported `metadata`/`generateMetadata`; handle errors with error.tsx boundaries.
- Dev server: `pnpm dev`. Typecheck: `pnpm tsc --noEmit`.

### supabase
- Use only if the archived `supabase-auth-backend` direction is revived; NOT active in the current local-first architecture.
- If used: supabase-js with SSR integration (@supabase/ssr), cookies for sessions, RLS policies tested per table.
- Verify JWT on Edge Functions; never disable without custom auth.

### judgment-day
- Parallel adversarial review protocol: launch two independent blind judge sub-agents on the same target, synthesize, apply fixes, re-judge.
- Trigger words: "judgment day", "review adversarial", "doble review", "juzgar".

### branch-pr
- Issue-first enforcement: create/open the GitHub issue before the PR; PR references the issue.
- Inspect status, diff, remote tracking, and base-branch diff before opening; return the PR URL.

### issue-creation
- GitHub issue creation workflow: bug reports and feature requests go through the issue template; link related change docs (PRD/migration).

### web-perf
- Audit Core Web Vitals (LCP, INP, CLS) with Chrome DevTools MCP; identify render-blocking resources, layout shifts, caching gaps.
- Bias to current documentation retrieval over pre-trained knowledge.
